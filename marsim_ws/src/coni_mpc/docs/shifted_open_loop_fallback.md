# A 路线：求解失败时顺序执行上次成功计划

`MpcController` 为每个实例缓存最后一次通过求解及有效性检查的完整
`7 × 20` 输入序列，包括相对速度、yaw rate 和三个 slack。失败求解的
预测数组不会覆盖该缓存。

| 本次控制调用 | 返回的控制 |
|---|---|
| 成功 | 新计划 `u0`；替换缓存，下一索引设为 1 |
| 随后第一次失败 | 缓存 `u1` |
| 随后第二次失败 | 缓存 `u2` |
| 连续失败至末端 | 缓存 `u19`，后续继续保持 `u19` |
| 尚无成功计划即失败 | 原有零命令回退 |

每次失败调用只推进一次，所有失败出口共用同一函数。slack 诊断和下一次
求解的 previous-input anchor 同步为本次选中的阶段输入。恢复成功后，
下一次失败从新计划的 `u1` 开始。失败状态仍报告为失败。

按本次确定的规则，索引按控制调用推进。当前预测步长为 0.1 s、仿真控制
周期为 0.02 s；本实现不按旧计划的时间年龄选取阶段，也不修改这两个周期。
因此这是指定的顺序开环回退，不声称严格执行旧预测的时间参数化。

数值仿真的惯性模式直接执行控制器返回的世界系命令；已移除失败时额外
覆盖为随平台运动的 hover 指令的分支。非惯性模式继续使用现有坐标转换，
发布前的世界系速度和 yaw 限幅保留。ACADO 模型、生成代码、Field-HOCBF
和 YAML 参数无需修改。

已有可选 world-command provenance CSV 追加：

- `applied_plan_stage`：成功为 0，回退为 1–19，无计划为 -1；
- `fallback_plan_exhausted`：回退到达末端阶段 19 时为 1；
- `plan_generation`：每接受一次新计划递增，失败时保持不变。

旧计划的约束满足性属于原求解的名义预测；新状态、平台运动或障碍物变化
后，回退命令的物理可行性及 HOCBF 满足性没有被重新认证。末端保持也不
构成终端安全控制器或递推可行性证明。

## 验证（2026-10-22）

`coni_mpc` 构建通过；`rostest coni_mpc route_a_fallback.test` 的三项测试通过：
无缓存失败、完整阶段顺序/末端保持/多实例/slack 与 anchor 同步，以及真实
不可行 ACADO 求解后的缓存保持、无效恢复拒绝和重新成功后的计划替换。
阶段精确比对使用公开恢复接口注入可区分输入；拒绝测试另使用实际成功求解
的原始计划。没有加入生产环境故障开关。

惯性与非惯性无障碍短仿真各 300 次控制，均无失败，独立复算发布映射/限幅
最大误差约 `8.9e-16`。另一个高转速工况有 155/300 次失败，均发生在对应
实例尚无成功缓存时，验证了无计划回退的发布链；该工况没有验证缓存阶段的
发布，也不与旧回退的轨迹作受控性能比较。全部仿真关闭障碍物和 CBF，
不代表避障或实飞验证。
