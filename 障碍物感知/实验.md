# 非惯性 Stage MPC-CBF 实验大纲

## 第一组：仿真实验大纲

### 1. 实验主线

- 主结论：`NI-Stage MPC-CBF` 相比 `NI-Frozen MPC-CBF` 改善安全-性能折中。
- 机理支撑：`stage-wise` 提高预测时域内非惯性预测一致性。
- 工程结论：方法具备实时在线部署可行性，并由后续实物实验进一步验证。

### 2. 对比方法

- 主对比：
  - `NI-Frozen MPC-CBF`
  - `NI-Stage MPC-CBF`
- 消融：
  - `NI-Frozen MPC`
  - `NI-Stage MPC`

### 3. 默认实验设置

- 所有实验默认包含：
  - 状态估计噪声
  - 一阶执行器滞后
  - `tau_v_xy = tau_v_z = 0.2 s`
- 所有方法共享：
  - 相同系统模型
  - 相同预测时域
  - 相同采样周期
  - 相同代价函数权重
  - 相同障碍物配置规则
  - 相同 CBF 参数
  - 相同求解器设置
  - 相同激活无人机集合 `active_uavs = 1,2,3`

### 4. 初始条件

- UAV 初始相对位置误差为 `0`
- UAV 初始相对速度误差为 `0`
- UAV 初始世界坐标由 UGV 初始位姿与相对编队偏置共同确定
- UAV 初始世界速度由 UGV 初始平动速度与编队偏置诱导的旋转输运速度共同确定

### 5. 场景设置

#### 5.1 基线场景

- `circle`
- 作用：
  - 作为弱时变非惯性场景
  - 验证当 `frozen` 近似本身成立时，`stage-wise` 不会带来明显退化

#### 5.2 主场景

- `figure-eight`
- 作用：
  - 作为主统计场景
  - 反复触发转弯进入、转弯退出、曲率翻转
  - 放大 `frozen` 假设失效带来的问题

### 6. 难度定义

- 难度主轴：**预测时域内非惯性项变化强度**
- `r, v, w` 是调节变量，不直接作为难度定义
- 当前已完成主批次采用对角线工况：
  - `KP=1`：`V=W=0.5`
  - `KP=2`：`V=W=1.0`
  - `KP=3`：`V=W=1.5`
  - `KP=4`：`V=W=2.0`
  - `KP=6`：`V=W=3.0`
- 在当前文档中：
  - 低速对应 `KP=1`
  - 中速对应 `KP=2,3`
  - 高速对应 `KP=4,6`
- 难度分层目标：
  - 低：预测时域内非惯性项变化弱
  - 中：预测时域内非惯性项变化中等
  - 高：预测时域内非惯性项变化强

### 7. 实验分组

#### 实验 I：纯跟踪机理验证

- 无障碍
- 无 CBF
- 对比：
  - `NI-Frozen MPC`
  - `NI-Stage MPC`
- 场景：
  - `circle`
  - `figure-eight`
- 目的：
  - 验证 `stage-wise` 是否改善非惯性项一致性
  - 验证 `stage-wise` 是否改善纯跟踪性能
- 当前已完成批次：
  - `circle`
  - `clean figure-eight`
  - `KP=1,2,3,4,6`
  - `100` 个配对 `noise seed`

#### 实验 II：安全约束主实验

- 有障碍
- 有 CBF
- 不加入随机障碍物
- 仅保留固定的 `figure-eight` 关键障碍物
- 对比：
  - `NI-Frozen MPC-CBF`
  - `NI-Stage MPC-CBF`
- 主场景：
  - `figure-eight`
- 目的：
  - 验证 `stage-wise + CBF` 是否改善安全-性能折中
- 当前已完成批次：
  - 固定关键障碍物 `figure-eight`
  - `KP=1,2,3,4,6`
  - `100` 个配对 `noise seed`

#### 实验 III：实时性实验

- 统计所有控制器的在线求解耗时
- 目的：
  - 验证 `stage-wise` 额外开销是否可接受
  - 支撑在线部署可行性结论

### 8. 障碍物与失败定义

- 障碍物优先布设在：
  - 转弯区
  - 曲率翻转区
  - 轨迹交叉区
- 失败定义：
  - 当前主结果图中的失败率采用离线阈值
    `minimum surface distance < 0.215 m`
  - 若写成中心距离形式，可等价表示为
    `d < r_uav + r_obs + 0.215 m`
- 主要安全指标：
  - `failure rate`
  - `CBF slack sum`
- 当前主文解释口径：
  - `KP=1..4` 主要看绝对 `failure rate` 降幅是否增大
  - `KP=6` 由于二值安全指标饱和到 `1.0 / 1.0`
  - 因此 `KP=6` 的安全性主要看 `CBF slack sum`

### 9. 随机种子含义

- 对 `circle` 和 `figure-eight`：
  - seed 不改变轨迹几何本身
- seed 可能改变：
  - 障碍物布局
  - 噪声 realization
- 对实验 I：
  - `obs = 0` 时，若噪声 seed 固定，则不同 seed 不会产生新的有效样本
  - 因此实验 I 的重复样本应通过改变 `noise seed` 获得
- 对实验 II：
  - 固定关键障碍物布局
  - 不同 seed 只改变 `noise realization`
  - 同一 seed 下所有控制器必须共享同一噪声 realization

### 10. 主要指标

#### 10.1 纯跟踪指标

- `tracking RMS`
- `peak tracking error`
- `prediction_horizon_rms_xy`
- `eq18_frot_mismatch_rms`
- 当前实现下，`prediction_horizon_rms_xy` 对 `frozen/stage` 基本重合，因此不作为主结论指标
- 当前批次未统计 `control smoothness`

#### 10.2 安全约束指标

- `failure rate`
- `CBF slack sum`
- `tracking RMS under safety constraints`
- 当前主图不再使用 `slack num`
- `CBF max slack` 与 `task completion rate` 可作为补充指标后续再加
- 当前主文主表顺序：
  - 先汇报全部 `tracking RMS`
  - 其中 `tracking RMS under safety constraints` 归入 `tracking` block
  - 再汇报 `failure rate` 与 `CBF slack sum`

#### 10.3 实时性指标

- `average solver time`
- `P95 solver time`
- `worst-case solver time`
- `feasibility rate`
- `deadline miss rate`

### 11. 统计规则

- 定性展示图：
  - 单次运行即可
  - 仅用于展示代表性轨迹、预测失配或 CBF 响应过程
- 所有定量结果不得只做一次
- 所有主对比实验使用配对随机种子
- 实验 I：
  - 采用固定轨迹
  - 通过不同 `noise seed` 重复运行
  - 当前主结果批次为 `100` 次重复
- 实验 II：
  - 通过不同 `noise seed` 重复运行
  - 当前主结果批次为 `100` 个配对 seed
- 实验 III：
  - 实时性统计直接汇总实验 I 和实验 II 的全部运行结果
- 连续指标报告：
  - `mean ± std`
  - `median`
  - `P95`
- 安全指标报告：
  - `failure count / total trials`
  - `failure rate`
- 统计口径：
  - `all-trial`
  - `common-success subset`

## 第二组：三无人机实物实验执行大纲

### 14.1 核心任务

- 正文实物实验只做一个主实验：
  - 在真实 `1 UGV + 3 UAV` 平台上，使用同一条 `figure-eight` UGV replay 和同一组实体障碍物，配对比较 `NI-Frozen MPC-CBF` 与 `NI-Stage MPC-CBF`。
- 该实验要回答的唯一问题：
  - 在 `active_uavs=1,2,3` 的真实多机 target-relative obstacle-avoidance 任务中，`stage-wise` 是否比 `frozen` 带来更低的团队跟踪误差、更低的 CBF 松弛需求，并且不增加阈值安全违规。

### 14.2 主实验定义

- 实验编号：
  - `HW-3UAV-Main`
- 平台：
  - `1` 台真实 UGV
  - `3` 台真实 UAV
  - motion-capture 或等价定位系统
  - 室内实体障碍物
- 控制器：
  - `NI-Frozen MPC-CBF`
  - `NI-Stage MPC-CBF`
- active UAV set：
  - `active_uavs=1,2,3`
- 场景：
  - `fixed-obstacle figure-eight + CBF`
- UGV 轨迹：
  - 固定 replay `bags/car1_cmd_vel_kp2_figure8_realcar_limit1.csv`
  - 对应 `KP=2`
  - 约束在 `linear.x <= 1.0 m/s`, `angular.z <= 1.0 rad/s`
- 控制频率：
  - `50 Hz`
  - 采样周期 `0.02 s`

### 14.3 三机编队定义

- 三台 UAV 同时执行 target-relative formation tracking。
- 编队偏置与仿真 `active_uavs=1,2,3` 口径保持一致。
- 若沿用当前代码默认 offset 逻辑，三机对应的 target-frame 偏置可写为：
  - `p_1^N = [0, r_hw, z_hw]^T`
  - `p_2^N = [0, -r_hw, z_hw]^T`
  - `p_3^N = [r_hw, 0, z_hw]^T`
- `r_hw` 和 `z_hw` 用实际硬件值回填。
- 若因场地或下洗流限制需要统一缩放编队，只允许做统一比例缩放，并在配置与正文中明确报告。

### 14.4 障碍物设置

- 障碍物固定不动。
- 障碍物位置围绕 figure-eight 的三个高风险区域布设：
  - 转弯区
  - 曲率翻转区
  - 交叉区
- 目标不是人为制造碰撞：
  - 目标是让 CBF 在局部时段真实激活，从而比较 `Frozen` 与 `Stage` 的 tracking-safety trade-off。

### 14.5 试验矩阵

| Pair ID | UGV replay | Obstacle layout | Controller A | Controller B | Initial formation |
| --- | --- | --- | --- | --- | --- |
| `P1` | same | same | `NI-Frozen MPC-CBF` | `NI-Stage MPC-CBF` | same |
| `P2` | same | same | `NI-Frozen MPC-CBF` | `NI-Stage MPC-CBF` | same |
| `P3` | same | same | `NI-Frozen MPC-CBF` | `NI-Stage MPC-CBF` | same |
| `P4` | same | same | `NI-Frozen MPC-CBF` | `NI-Stage MPC-CBF` | same |
| `P5` | same | same | `NI-Frozen MPC-CBF` | `NI-Stage MPC-CBF` | same |

- 正文目标：
  - `5` 组 paired trials，即 `10` 次三机飞行
- 最低可接受数量：
  - `3` 组 paired trials，即 `6` 次三机飞行
- 每个 pair 内只允许改变：
  - `ugv_rollout_mode`
- 其余必须保持一致：
  - UGV replay
  - 障碍物布局
  - 三机初始编队
  - 求解器参数
  - CBF 参数

### 14.6 单次运行流程

- Step 1：摆放并测量实体障碍物，记录中心位置与半径。
- Step 2：让 UGV 和三台 UAV 回到规定初始位姿。
- Step 3：确认三台 UAV 的 target-frame offsets 与 `active_uavs=1,2,3` 一致。
- Step 4：启动日志记录。
- Step 5：播放固定的 UGV figure-eight replay。
- Step 6：运行 `NI-Frozen MPC-CBF` 或 `NI-Stage MPC-CBF`。
- Step 7：完成整条 replay 后停止日志。
- Step 8：同一 pair 中切换另一个控制器，重复 Step 2 到 Step 7。

### 14.7 需要保存的原始数据

- 每次运行保存一个 run folder。
- 命名建议：
  - `hardware_3uav_fig8_kp2_pair01_frozen`
  - `hardware_3uav_fig8_kp2_pair01_stage`
- 每个 run folder 至少包含：
  - `ugv_state.csv`
  - `uav1_state.csv`
  - `uav2_state.csv`
  - `uav3_state.csv`
  - `uav_cmd_vel.csv`
  - `solver_log.csv`
  - `cbf_log.csv`
  - `inter_uav_distance.csv`
  - `run_config.yaml`
- `run_config.yaml` 必须记录：
  - controller name
  - `ugv_rollout_mode`
  - `active_uavs=1,2,3`
  - UGV replay 文件名
  - 三台 UAV relative offsets
  - obstacle centers and radii
  - UAV radius and obstacle radius
  - CBF parameters
  - control rate
  - date and run ID

### 14.8 离线统计指标

| 指标 | 计算对象 | 用途 |
| --- | --- | --- |
| team target-relative tracking RMS | 三台 UAV 的团队聚合误差 | 主 tracking 指标 |
| max-UAV tracking RMS | 三台 UAV 中 RMS 最大者 | 防止团队均值掩盖单机掉队 |
| peak tracking error | 三台 UAV 中最大瞬时误差 | 反映局部极端偏差 |
| minimum obstacle surface distance | 全部 UAV-obstacle pair 中最小表面距离 | 主障碍物安全指标 |
| minimum inter-UAV surface distance | 三台 UAV 两两最小表面距离 | 主机间安全指标 |
| violation count / rate | 任一安全对象低于阈值的 trial 计数 | 主二值安全指标 |
| team CBF slack sum | 三台 UAV slack 的团队累计或保守聚合 | 主 feasibility 指标 |
| solve time mean / P95 / peak | 三台 UAV 求解时间的团队聚合 | 主实时性指标 |
| deadline miss rate | solve time `> 20 ms` 的比例 | 硬件实时性补充指标 |

- 安全阈值统一为：
  - `minimum surface distance < 0.215 m`
- 对 UAV-obstacle：
  - `d < r_uav + r_obs + 0.215 m`
- 对 UAV-UAV：
  - `d < 2 r_uav + 0.215 m`

### 14.10 实验员执行清单

- 实验前确认：
  - `bags/car1_cmd_vel_kp2_figure8_realcar_limit1.csv` 能稳定驱动 UGV
  - 三台 UAV 能稳定起飞并保持初始编队
  - 三台 UAV 的 relative offsets 已经写入配置并记录
  - 实体障碍物位置已经测量并记录
  - `Frozen` 与 `Stage` 的配置文件只差 `ugv_rollout_mode`
- 每个 pair 确认：
  - 不改变 UGV replay
  - 不移动障碍物
  - 不改变三机初始编队和 offset
  - 两次运行都保存完整日志
- 实验后确认：
  - 每次运行都能计算 team tracking RMS
  - 每次运行都能计算 minimum obstacle surface distance
  - 每次运行都能计算 minimum inter-UAV surface distance
  - 每次运行都能计算 team slack sum
  - 每次运行都能计算 solve time mean / P95 / peak
